Lesson 01

What is Claude Code?
什麼是 Claude Code？

本節概念：Agentic Tool · AI Agent · Context Window · Permission Mode
前往 YouTube 觀看影片

本節重點 Key Takeaways

  1. Claude Code 是 Agentic 程式設計工具，可直接存取你的檔案、終端機與程式碼庫，不需要複製貼上。
  2. 與 Claude AI 的差異：Claude Code 能「自己進去做事」，而非只輸出文字讓你自己操作。
  3. AI Agent = 能與環境互動、自主執行行動來達成目標的軟體。
  4. Context Window（情境視窗） = Claude 的工作記憶，有容量上限，無法存放所有內容。
  5. 預設行為：執行操作前會詢問許可；Claude Code 並非完美，可能誤解意圖或引入錯誤。

核心概念 Core Concepts

Agentic Loop 代理循環

接收 prompt → 收集情境 → 呼叫模型 → 執行行動 → 驗證結果 → 若未達標則循環重試。

Tools 工具

讓 Agent 能「做事」的能力模組，例如讀取檔案、搜尋網頁、執行建置程式化腳本等。

Context Window 情境視窗

Claude 的工作記憶，存放對話記錄、檔案內容、指令輸出等。容量有限，需策略性管理。

Installing Claude Code
安裝 Claude Code

本節概念：Install · Platform Setup · Auto Update
前往 YouTube 觀看影片

本節重點 Key Takeaways

  1. Mac / Linux / WSL：用 curl 安裝（支援自動更新）；Homebrew 可用但不自動更新。
  2. Windows：PowerShell Invoke-RestMethod、curl 或 winget（winget 不自動更新）。
  3. 啟動方式：進入專案目錄後執行 claude，首次需設定色彩主題並登入帳號。
  4. Claude 可存取你執行指令的目錄及其所有子資料夾。
  5. 帳號類型：Pro、Max、Enterprise 或 API Key 皆可。

安裝指令速查 Install Commands

Mac / Linux / WSL

# 推薦（支援自動更新）
curl -fsSL https://claude.ai/install.sh | sh

# Homebrew（不自動更新）
brew install --cask claude-code

Windows

# PowerShell
Invoke-RestMethod -Uri https://claude.ai/install.ps1 | Invoke-Expression

# winget（不自動更新）
winget install Anthropic.ClaudeCode

Lesson 03

How Claude Code Works
Claude Code 如何運作

本節概念：Agentic Loop · Tools · Compaction · Permission Modes
前往 YouTube 觀看影片

本節重點 Key Takeaways

  1. Agentic Loop（代理循環）：Prompt → 收集情境 → 呼叫模型 → 執行行動 → 驗證結果 → 未達標則循環。
  2. Tools（工具） 是 Agent 的核心骨架，讓 Claude 能「做事」而非只輸出文字。
  3. 情境視窗接近上限時，Claude 會自動 compact（壓縮），可能遺失部分細節。
  4. 三種許可模式：預設（每次詢問）、Auto Accept（自動接受編輯）、Plan Mode（唯讀規劃）。
  5. Claude Code 使用語意搜尋（Semantic Search）判斷何時呼叫哪個工具。

Agentic Loop 代理循環

使用者輸入 Prompt
       ↓
收集所需情境 (Context)
       ↓
呼叫 LLM（回傳文字或工具呼叫）
       ↓
執行行動（編輯檔案、執行指令…）
       ↓
驗證結果
       ↓
達標？→ Yes → 等待下一個 Prompt
       → No  → 回到循環頂端

三種許可模式 Permission Modes

模式說明切換
Default 預設每次操作前詢問許可預設狀態
Auto Accept自動接受檔案編輯；執行指令仍需確認Shift + Tab
Plan Mode僅使用唯讀工具，先規劃再執行Shift + Tab（再切）

關鍵詞彙 Vocabulary

英文中文說明
Agentic Loop代理循環Claude 自主執行任務的反覆循環機制
Tool Call工具呼叫Claude 決定使用特定工具的行動
Compaction壓縮情境視窗接近上限時，自動摘要舊內容釋放空間
Semantic Search語意搜尋根據語義判斷何時呼叫哪個工具
Verification驗證Claude 確認執行結果是否達到 prompt 目標
實作練習 Try It Now
  1. 啟動 Claude Code，連按 Shift + Tab 幾次，觀察三種模式如何切換
  2. 在 Default 模式下，請 Claude 修改某個檔案——注意它如何詢問你的許可
  3. 切換到 Auto Accept 模式，執行同樣的任務，比較流程有何不同
  4. 觀察工具呼叫列表，確認你能看出 Agentic Loop 的每一個步驟

Lesson 04

Your First Claude Code Prompt
第一個 Prompt

本節概念：Prompt Writing · Plan Mode · Auto Accept
前往 YouTube 觀看影片

本節重點 Key Takeaways

  1. 用自然語言與 Claude Code 對話，如同對人類說話。
  2. Shift + Tab 切換模式：Auto Accept ↔ 手動確認 ↔ Plan Mode。
  3. Plan Mode：用唯讀工具分析程式碼庫 → 回傳詳細計畫 → 確認後才執行。
  4. Prompt 原則：越具體越好，說清楚目標、現有限制、預期結果。
  5. Plan Mode 的計畫可修改後再 Approve，是最佳的「開始執行前修正」節點。

Prompt 寫作技巧

做 ✅不做 ❌
說明「我需要達成什麼」只說「幫我改這個」
描述現有系統的限制與偏好不說明使用的框架或風格
指定預期結果的樣子留下模糊的成功標準
一次聚焦一個目標把太多功能塞進一個 prompt

Plan Mode 使用流程

Shift + Tab → 進入 Plan Mode
輸入詳細 Prompt（說清楚目標與限制）
→ Claude 分析程式碼庫，返回計畫
審視計畫 → 修改 → Approve → Claude 開始執行
好的 Prompt 範例
"My app needs a dark mode implemented across the entire app. Create a toggle switch on the header that allows user to toggle between light and dark mode. Find a good contrast color that works based on my existing light theme."

包含了：目標（dark mode）、位置（header toggle）、限制（配合現有 light theme）

關鍵詞彙 Vocabulary

英文中文說明
Plan Mode規劃模式唯讀分析，先給計畫再執行
Auto Accept自動接受自動核准所有檔案編輯
Approve核准確認 Plan Mode 的計畫並開始執行
Course Correct修正方向執行中途調整 Claude 的做法
實作練習 Try It Now
  1. 想一個你想在專案裡實作的小功能（例如：加一個按鈕、新增 API endpoint）
  2. 先用一句模糊的話下 prompt（例如：「加個 dark mode」），觀察 Claude 的回應
  3. 按照本節技巧，重新寫一個具體 prompt：包含目標、位置、限制、預期樣子
  4. 進入 Plan Mode，貼入具體 prompt，比較計畫的詳細度有何差異

Lesson 05

The CLAUDE.md File
CLAUDE.md 持久記憶檔案

本節概念：Persistent Memory · Hierarchy · /init
前往 YouTube 觀看影片

本節重點 Key Takeaways

  1. CLAUDE.md = Claude Code 的持久記憶，每次 session 啟動時自動讀取。
  2. 沒有 CLAUDE.md 時，Claude 每次都要從頭理解程式碼庫，容易做出假設與錯誤。
  3. /init 指令：讓 Claude 根據你的程式碼庫自動生成初始 CLAUDE.md。
  4. 層級結構：專案級（根目錄，團隊共用）→ 使用者級（個人設定，跨所有專案）。
  5. 最佳實踐：先不加，觀察哪些地方需要反覆糾正，再精簡加入。

CLAUDE.md 層級 Hierarchy

~/.claude/CLAUDE.md          ← 使用者級（個人偏好，跨所有專案）
                                  只有你看得到

/your-project/CLAUDE.md      ← 專案級（根目錄，check in 版本控制）
                                  整個團隊共用

CLAUDE.md 建議填入內容

## Tech Stack 技術堆疊
- Next.js 15 (App Router) / Tailwind CSS / Drizzle ORM

## Commands 常用指令
- dev: npm run dev  |  test: npm test  |  lint: npm run lint

## Code Style 程式碼風格
- 2 space indentation  |  Named exports only

## Rules 規則
- Use server actions instead of API routes
最佳實踐 Best Practice
先不加 CLAUDE.md，觀察哪些地方需要反覆糾正，再把那些規則加進去。保持檔案精簡，只存放真正必要的資訊。

三個使用技巧

  1. 糾正 Claude 的行為後，告訴他：「把這個規則存進 CLAUDE.md」
  2. 用 @檔案路徑 引用文件，讓 Claude 直接參考
  3. 從 /init 自動生成起點，再根據需要精簡

關鍵詞彙 Vocabulary

英文中文說明
CLAUDE.md—Claude Code 的持久記憶設定檔（Markdown 格式）
Persistent Memory持久記憶跨 session 保留的知識與設定
/init—讓 Claude 自動生成 CLAUDE.md 的指令
Project-level專案級放在根目錄，整個團隊共用
User-level使用者級放在個人設定資料夾，只有自己用
實作練習 Try It Now
  1. 在你的專案根目錄，執行 /init，讓 Claude 自動生成初始 CLAUDE.md
  2. 檢視生成的內容，確認技術堆疊、指令、風格描述是否正確，手動補齊遺漏的部分
  3. 加入一條你自己的規則（例如縮排、命名習慣、禁止某種寫法）
  4. 關掉 session，重新開啟，輸入同樣的任務——確認 Claude 已直接套用你的設定

Lesson 06

Explore → Plan → Code → Commit
核心工作流程

本節概念：Workflow · Plan Mode · Sub Agent · Commit
前往 YouTube 觀看影片

本節重點 Key Takeaways

  1. 核心工作流程：Explore → Plan → Code → Commit，不要直接跳到 Code。
  2. 多數人直接下指令產生程式碼，導致大量事後修正；計畫確認前才是最佳修正節點。
  3. Plan Mode 可同時完成 Explore + Plan，是進入前兩步最快的方式。
  4. 為 Claude 提供可驗證的成功標準（測試套件、Claude in Chrome），讓他自行確認完成。
  5. Commit 前用 sub agent 做 code review，再讓 Claude 生成 commit message。

工作流程 Workflow

Explore探索
Plan規劃 ✅修正點
Code編碼
Commit提交
備注：名稱差異
本講義依課程影片使用「Code」；Anthropic 官方文件（code.claude.com）將同一步驟標示為「Implement」。兩者指相同流程，「Implement」語意較廣，泛指所有實作工作——不限於程式設計，修改設定、資料遷移、撰寫文件等皆屬之。

Step 1 & 2 — Explore + Plan（用 Plan Mode）

Shift + Tab → 進入 Plan Mode → 輸入目標 Prompt
→ Claude 讀取檔案、搜尋文件、提問澄清
→ 回傳詳細計畫 → 審視 → 修改 → Approve

Step 3 — Code

讓 Claude 依計畫逐步執行；隨時 course-correct；把反覆修正的規則存進 CLAUDE.md。

Step 4 — Commit

1. 用 sub agent 做 code review
2. 讓 Claude 生成 commit message
3. Push → 開始下一個功能

讓 Claude 自我驗證的工具

工具用途
測試套件（Test Suite）Claude 跑測試確認功能正確
Claude in Chrome 擴充Claude 控制瀏覽器實際測試 UI
Lint / Type Check確保程式碼品質

Lesson 07

Context Management
情境視窗管理

本節概念：/compact · /clear · /context · Sub Agent · Token
前往 YouTube 觀看影片

本節重點 Key Takeaways

  1. Context Window = Claude 的工作記憶，所有輸入、工具執行結果、對話都佔空間。
  2. /compact：壓縮對話並保留摘要，繼續當前功能開發時使用。
  3. /clear：完全清除，開始全新任務或新功能時使用。
  4. /context：查看目前情境使用狀況、佔用分佈與視覺化圖表。
  5. 減少消耗的技巧：提示詞要具體、關掉不用的 MCP server、善用 sub agent。

指令速查 Commands

/compact
壓縮對話，保留摘要
繼續同一功能用
/clear
完全清除
開始新功能用
/context
查看 context
使用狀況

compact vs clear 決策樹

還在做同一個功能？
  Yes → /compact（壓縮，保留摘要繼續工作）
  No  → /clear（清除，全新開始避免舊對話影響）

減少 Context 消耗的 5 個技巧

  1. 提示詞要具體：模糊 prompt 迫使 Claude 探索更多檔案
  2. 停用不需要的 MCP server：每個 server 的工具定義都佔 context
  3. 用 sub agent 委派任務：獨立 context，只回傳摘要給主 agent
  4. 把常用規則放進 CLAUDE.md：不需要 Claude 每次重新探索
  5. 定期 /compact：大 session 中途就壓縮，避免細節遺失

關鍵詞彙 Vocabulary

英文中文說明
Context Window情境視窗Claude 的工作記憶容量
Compaction壓縮自動或手動摘要舊內容，釋放空間
Sub Agent子代理程式有獨立 context 的 Claude 實例，只回傳結果
Token—衡量 context 佔用量的單位
實作練習 Try It Now
  1. 開啟一段正在進行的 session，執行 /context，看看哪些類別佔用最多空間
  2. 繼續做一段開發工作，再次執行 /context，觀察數字的變化
  3. 在功能還沒做完但 context 開始偏高時，執行 /compact，確認摘要是否保留了關鍵資訊
  4. 下次開始新功能前，養成先執行 /clear 的習慣，感受乾淨 context 帶來的差異

Lesson 08

MCP in Claude Code
整合外部工具

本節概念：Model Context Protocol · HTTP Server · stdio · Scope
前往 YouTube 觀看影片

本節重點 Key Takeaways

  1. MCP（Model Context Protocol） = 讓 Claude Code 連接外部工具與資料來源的開放標準。
  2. 兩種 server 類型：HTTP（遠端服務，由服務商代管）、stdio（本機程式）。
  3. 三種 scope：local（本機本專案）、user（個人跨專案）、project（.mcp.json，團隊共用）。
  4. MCP server 的工具定義佔用 context window，不用的要用 /mcp 停用。
  5. 工具佔用超過 10% context 時，Claude 自動切換 tool search mode（效果較差）。

三種 Scope（作用範圍）

Local 本機本專案
只有你，只在這個專案有效
User 使用者
只有你，跨所有專案都可用
Project 專案級
整個團隊共用，透過 .mcp.json check in

常用操作

# 新增 MCP server
claude mcp add [server-name]

# 在 session 內管理（查看狀態、停用）
/mcp

MCP vs CLI 選擇指南

情境建議做法原因
GitHub 操作用 gh CLI更節省 context
AWS 操作用 aws CLI更節省 context
Notion / Linear（無 CLI）用 MCP server唯一選項
團隊統一設定project scope + .mcp.json自動同步給所有人

關鍵詞彙 Vocabulary

英文中文說明
MCPModel Context Protocol連接外部工具的開放標準
HTTP ServerHTTP 伺服器遠端服務提供的 MCP server
stdio Server標準 I/O 伺服器在本機執行的 MCP server
Tool Search Mode工具搜尋模式工具太多時的自動備用模式，效果較差
.mcp.json—存放 project scope MCP 設定的檔案
實作練習 Try It Now
  1. 在 session 中執行 /mcp，確認目前有哪些 server 連接，停用你現在不需要的
  2. 選一個與你專案相關的 MCP server 安裝（推薦：Context7 取得最新套件文件）
  3. 安裝後，要求 Claude 用這個工具完成一個真實任務，觀察它如何呼叫外部資料
  4. 如果你的團隊共用同一個 repo，建立 .mcp.json 並把 server 設定 check in

Hooks in Claude Code
確定性自動化

本節重點 Key Takeaways

  1. Hooks = 確定性執行的自動化，不像 CLAUDE.md 的「建議」，Hooks 每次都一定執行。
  2. 常見用途：自動格式化（prettier / gofmt）、記錄指令、封鎖危險操作、任務完成通知。
  3. 設定在 settings.json，可 check in 版本控制讓整個團隊共用相同規則。
  4. Exit code 規則：0 = 繼續執行，2 = 阻擋並把 stderr 回傳給 Claude。
  5. 核心原則：某件事必須每次都發生 → 放進 Hook，不要放進 prompt 或 CLAUDE.md。
「如果某件事必須每次都發生，不要放進 prompt，放進 Hook。」

5 種 Hook 事件

事件觸發時機常見用途
UserPromptSubmit你送出 prompt 時（Claude 處理前）前置驗證、記錄
PreToolUse工具呼叫前封鎖危險操作
PostToolUse工具呼叫後自動格式化、記錄
NotificationClaude 發送通知時轉發到 Slack / 系統通知
StopClaude 完成回應時任務完成通知

Exit Code 規則

Exit 0
繼續執行（proceed）
工具呼叫正常進行
Exit 2
阻擋（block）
stderr 回傳給 Claude，Claude 知道原因後調整

最常用：自動格式化 PostToolUse Hook

{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|MultiEdit",
      "command": "bash -c 'ext=${TOOL_INPUT_FILE##*.};
        case $ext in
          ts|tsx) prettier --write $TOOL_INPUT_FILE ;;
          go)     gofmt -w $TOOL_INPUT_FILE ;;
          py)     ruff format $TOOL_INPUT_FILE ;;
        esac'"
    }]
  }
}

實作練習 Try It Now
  1. 在 settings.json 加入一個 PostToolUse hook，讓每次 Claude 編輯檔案後自動執行格式化（參考本節的範例 JSON）
  2. 請 Claude 修改一個檔案，確認 hook 有自動觸發、格式化有實際執行
  3. 加入一個 PreToolUse hook，封鎖一個你覺得危險的操作（例如：包含 rm -rf 的指令）
  4. 盤點你的工作流程中有哪些「一定要做」的步驟，把它們都移進 hook——讓規則不再依賴你記得說
